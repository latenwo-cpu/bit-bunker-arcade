WHY THE DEPLOY KEPT FAILING
----------------------------
Removing the <a> link to the .apk in index.html was necessary but not
sufficient. Firebase Hosting scans every file inside your "public"
folder during `firebase deploy` and rejects the whole deploy if it
finds a .apk/.exe/.dll/.bat file in there — regardless of whether
anything on your site actually links to it. The file itself has to be
gone from public/ (and www/, since that's your Capacitor source dir).

WHAT'S FIXED IN THIS ZIP
--------------------------
1. Deleted public/downloads/ and www/downloads/ entirely (the .apk
   files that were still sitting there).
2. The "Get it on Android" button in public/index.html and
   www/index.html now points to your GitHub Release instead:
   https://github.com/latenwo-cpu/bit-bunker-arcade/releases/download/build-11/app-release.apk
3. Added a safety net in firebase.json's hosting.ignore list, so even
   if an .apk/.exe/.dll/.bat ever ends up back inside public/ by
   accident, Firebase's own deploy step will just skip that file
   instead of failing the whole deploy:
     "**/*.apk", "**/*.exe", "**/*.dll", "**/*.bat", "**/downloads/**"

WHAT'S NOT IN THIS ZIP (regenerate locally, don't need to be shipped)
-----------------------------------------------------------------------
- node_modules/          -> run: npm install
- android/build/          -> generated by Gradle
- android/.gradle/        -> generated by Gradle
- android/app/build/      -> generated by Gradle
- android/app/release/    -> your last built APK; rebuild if needed

HOW TO USE
-----------
1. Unzip this over your current "Arcade Games" folder (overwrite).
2. cd into it, run: npm install
3. firebase deploy
   (should now succeed - public/ contains 0 apk/exe/dll/bat files)
